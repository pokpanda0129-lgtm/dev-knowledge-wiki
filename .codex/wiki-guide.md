# wiki-guide

개발 지식 위키를 자연어 요청으로 운영하기 위한 내부 가이드입니다.

사용자는 슬래시 커맨드를 외울 필요가 없습니다. 개발 지식 문서를 생성, 수정, 리뷰, 색인 정리, 이미지 추가하려는 일반 문장을 위키 작업으로 인식합니다.

사용자가 skill 이름을 직접 말하지 않아도 개발 지식 위키 작업이면 `dev-knowledge-wiki` skill을 사용합니다. 작업이 복합적이고 병렬 검토가 도움이 되면 subagent 사용도 고려합니다.

## 자연어 요청 예시

```text
frontend의 SSR과 CSR의 차이를 md로 만들어줘
java Stream map과 flatMap 차이를 정리해줘
frontend 문서 목록 README에 정리해줘
이 글에 비개발자도 이해하기 쉬운 그림 추가해줘
```

## 요청 의도 구분

### 새 문서 생성

사용자가 특정 주제를 마크다운으로 만들기, 작성하기, 정리하기, 요약하기를 요청하면 실행합니다.

작업 흐름:

1. 제목, 카테고리, 저장 경로, 대상 독자, 섹션 계획을 정합니다.
2. `skills/dev-knowledge-wiki/assets/article.md`를 기준으로 문서 초안을 잡습니다.
3. `skills/dev-knowledge-wiki/references/writing.md`로 문서 구조와 한국어 작성 톤을 맞춥니다.
4. 글만 읽어도 장면이 떠오르는 짧은 예시 스토리를 작성합니다.
5. `skills/dev-knowledge-wiki/references/accuracy-review.md`로 비유와 기술 사실을 검증합니다.
6. 마크다운 파일을 만듭니다.
7. 명확성, 길이, 예시 스토리의 선명함을 검토합니다.
8. 필요하고 안전하다면 도메인 README를 갱신합니다.

에이전트 사용 조건:

- 작업을 계획, 예시 스토리 구성, 리뷰로 나누면 품질이 좋아지는 경우 `skills/dev-knowledge-wiki/references/subagents.md`를 따릅니다.
- 사용자가 subagent 사용을 원하지 않는다고 말하면 메인 Codex만 사용합니다.
- 그 외에는 메인 Codex가 동일한 역할 기준을 내부 체크리스트로 사용합니다.

### 기존 문서 리뷰

사용자가 기존 문서를 리뷰, 점검, 개선, 축약, 실무형으로 변경해달라고 요청하면 실행합니다.

작업 흐름:

1. 대상 마크다운 파일을 읽습니다.
2. 명확성, 길이, 예시 스토리의 선명함을 검토합니다.
3. 사용자가 수정을 요청했다면 필요한 부분만 고칩니다.
4. 문서는 간결하게 유지합니다.

### 이미지 추가 또는 갱신

사용자가 이미지, 다이어그램, 흐름도, 시각 설명, 코드 스크린샷을 요청하면 실행합니다.

작업 흐름:

1. 문서나 주제를 읽습니다.
2. `skills/dev-knowledge-wiki/references/visuals.md`로 이미지 유형을 정합니다.
3. 단어 뜻과 짧은 예시 스토리 흐름에 연결되는 이미지를 만듭니다.
4. 문서 옆 `assets` 폴더에 이미지를 저장합니다.
5. 마크다운 이미지 참조를 갱신합니다.

### 인덱스 갱신

사용자가 README, 카테고리, 문서 목록, 위키 인덱스 정리를 요청하면 실행합니다.

작업 흐름:

1. 대상 도메인 아래의 마크다운 파일을 찾습니다.
2. 카테고리 폴더 기준으로 문서를 묶습니다.
3. 도메인 README를 갱신합니다.
4. 기존 README의 유용한 내용은 유지합니다.

## 기본 문서 구조

```md
# 주제명

## 단어 뜻

## 예시 스토리

## 한 줄 요약

## 개념 설명

## 그래서 뭐가 좋은데? <!-- 비교형 문서에서만 선택 -->
```

## 운영 원칙

자연어 요청을 우선합니다. 이 파일은 사용자가 직접 호출해야 하는 명령어가 아니라, 위키 작업을 처리할 때 참고하는 내부 가이드로 사용합니다.
