# 시각 자료 규칙

## 목표

사용자가 이미지나 다이어그램을 요청했을 때만, 글의 예시 스토리를 보조하는 시각 자료를 만듭니다.

## 선호하는 이미지 유형

1. 단어 뜻과 짧은 예시 스토리를 떠올리기 위한 story 이미지
2. 요청 흐름 또는 데이터 흐름을 예시 스토리처럼 보여주는 이미지
3. 비교 개념을 같은 예시 스토리 구도 안에 묶은 이미지

## 규칙

- 별도 `그림으로 이해하기` 섹션을 만들지 않습니다.
- 기본 문서에는 이미지를 넣지 않습니다.
- 사용자가 이미지를 요청한 경우에만 `예시 스토리` 섹션 안에 배치합니다.
- 이미지는 용어 설명과 짧은 예시 스토리 뒤에 배치합니다. 독자가 단어 뜻과 예시 스토리를 먼저 읽고, 바로 아래 이미지로 확인하는 순서를 유지합니다.
- 이미지는 단순한 한 장면보다 예시 스토리의 흐름을 보여주는 2~4컷 구성을 우선합니다.
- 아키텍처, 렌더링, 생명주기, 데이터 흐름은 단순한 다이어그램으로 설명합니다.
- 비개발자도 이해할 수 있게 만듭니다.
- 개념 설명에 도움이 되지 않는 장식 이미지는 피합니다.
- 라벨은 짧게 작성합니다.
- 이미지 라벨은 문서의 `단어 뜻`과 `예시 스토리`에서 사용한 핵심 단어를 그대로 사용합니다. 예를 들어 설명이 `부품`, `조립 설명서`, `완성된 세트`라면 이미지에서도 `완성 HTML`처럼 다른 단어로 바꾸지 않습니다.
- 비교 이미지는 비교 대상의 구도를 맞춥니다. 예를 들어 CSR과 SSR을 비교한다면 둘 다 `Server -> Browser` 같은 같은 방향, 같은 요소 배치, 같은 시각 문법으로 그리고 차이만 다르게 표현합니다.
- 비교 이미지에서 한쪽만 비유 수준이 다르거나, 한쪽만 도표이고 다른 한쪽은 장면처럼 보이게 만들지 않습니다.
- 이미지는 문서 옆 `assets` 폴더 아래에 저장합니다.
- 이미지가 아직 생성되지 않았다면 깨진 링크를 넣지 말고 필요한 이미지 설명만 작성합니다.

## 이미지 생성 설명 패턴

이미지를 생성해야 한다면 다음 항목을 정리합니다.

- 개념
- 대상 독자
- 짧은 예시 스토리
- 핵심 라벨
- 레이아웃
- 색상과 스타일 제약
- 저장 경로
