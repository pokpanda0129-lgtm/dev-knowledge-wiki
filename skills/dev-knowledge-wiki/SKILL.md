# dev-knowledge-wiki

개발 지식 위키 문서를 일관된 형식으로 작성하기 위한 프로젝트 전용 skill입니다.

## 기본 흐름

1. 사용자가 skill 이름을 직접 말하지 않아도 개발 지식 위키 작업이면 이 skill을 사용합니다.
2. 요청 주제의 도메인과 카테고리를 정합니다.
3. `assets/article.md`를 기본 템플릿으로 사용합니다.
4. 문서 작성 규칙은 `references/writing.md`를 따릅니다.
5. 사용자가 이미지나 다이어그램을 명시적으로 요청한 경우에만 `references/visuals.md`를 읽고 이미지를 추가합니다.
6. 문서 작성 후 `references/accuracy-review.md`로 비유, 단정 표현, 기술 사실을 검증합니다.
7. 작업이 복합적이고 병렬 검토가 도움이 되면 `references/subagents.md`를 읽고 실제 subagent 사용을 고려합니다.
8. 문서를 작성한 뒤 길이, 이해 쉬움, 예시 스토리의 선명함을 점검합니다.

## 저장 규칙

- 도메인 문서는 `frontend/`, `java/` 같은 도메인 폴더 아래에 둡니다.
- 카테고리가 분명하면 하위 폴더를 만듭니다.
- 이미지를 별도로 만들 때는 문서와 같은 카테고리 폴더의 `assets` 아래에 둡니다.

예시:

```text
frontend/rendering/ssr-vs-csr.md
java/oop/overloading-vs-overriding.md
```

## 문서 기본 순서

```md
# 주제명

## 단어 뜻
## 예시 스토리
## 한 줄 요약
## 개념 설명
```

## 주의

- 사용자는 별도 커맨드를 외울 필요가 없습니다.
- 요청받은 범위를 넘어서는 문서나 도구를 만들지 않습니다.
- 문서가 비교형이 아니라 단일 개념이면 비교표를 강제로 넣지 않습니다.
- 처음 보는 용어는 `단어 뜻`에서 먼저 풀고, `예시 스토리`에서 기억할 장면을 잡아줍니다.
- 쉬운 비유를 쓰더라도 기술적 사실이 흐려지지 않게 검증합니다.
- 기본 문서에는 이미지를 넣지 않습니다. 글만으로 장면이 떠오르게 씁니다.
- 사용자가 이미지를 요청한 경우에만 `예시 스토리` 영역 아래에 넣습니다.
- 이미지가 아직 없으면 깨진 이미지 링크를 넣지 말고 텍스트만 작성합니다.
