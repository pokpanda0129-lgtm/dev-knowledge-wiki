# OpenResty

## 단어 뜻

- `OpenResty`: Nginx 기반 웹 플랫폼입니다. Nginx에 LuaJIT와 여러 모듈을 묶어, 요청 처리 중 Lua 코드로 판단이나 가공을 할 수 있게 만든 도구입니다.
- `Nginx`: 빠른 웹 서버이자 reverse proxy입니다. 정적 파일 제공, 프록시, 로드밸런싱, 캐시 같은 일을 잘합니다.
- `LuaJIT`: Lua 코드를 빠르게 실행하기 위한 런타임입니다. OpenResty는 이 LuaJIT를 이용해 Nginx 요청 처리 흐름에 스크립트 로직을 넣을 수 있습니다.
- `reverse proxy`: 브라우저 요청을 먼저 받아 필요한 판단을 한 뒤, 뒤쪽 서버인 Nuxt/Nitro나 WAS로 대신 전달하는 입구 역할입니다.

## 예시 스토리

백화점 입구에 안내 직원이 서 있습니다. 손님이 오면 직원은 먼저 표지판만 보고도 답할 수 있는 질문인지 확인합니다. “화장실은 어디예요?”처럼 자주 묻는 질문이면 바로 답하고, “이전 행사장은 어디로 옮겼어요?”처럼 정해진 안내가 있으면 새 위치로 보내줍니다.

그런데 상품 재고나 회원 할인처럼 안쪽 사무실 확인이 필요한 질문이면, 안내 직원은 손님을 직접 사무실로 들여보내지 않고 상담 데스크나 업무 부서로 대신 연결합니다. 손님 입장에서는 입구 직원만 만났지만, 뒤에서는 어떤 질문을 어디로 보낼지 계속 판단하고 있습니다.

가끔은 단순 전달만으로 부족합니다. VIP 손님인지 확인해 다른 줄로 안내하거나, 자주 묻는 안내문을 잠깐 보관해 다음 손님에게 더 빨리 보여줄 수도 있습니다. OpenResty는 이런 입구 안내 직원처럼 요청을 받고, 빠르게 답하거나, 뒤쪽 서버로 보내거나, 간단한 규칙을 적용하는 역할을 합니다.

## 한 줄 요약

OpenResty는 Nginx의 빠른 입구 서버 역할에 Lua 스크립트 능력을 더한 웹 플랫폼입니다. 마이그레이션 구조에서는 Browser와 Nuxt/Nitro 또는 WAS 사이에서 라우팅, 프록시, 캐시, 리다이렉트 같은 앞단 처리를 맡습니다.

## 개념 설명

OpenResty는 단순히 “Nginx와 비슷한 것”이라기보다, Nginx 기반에 LuaJIT와 여러 모듈을 함께 묶은 웹 플랫폼입니다. 공식적으로도 OpenResty는 확장된 Nginx core, LuaJIT, Lua 라이브러리, 여러 Nginx 모듈을 통합한 형태로 설명됩니다.

일반 Nginx 설정만으로도 정적 파일 제공, reverse proxy, 캐시, 로드밸런싱을 할 수 있습니다. OpenResty를 쓰면 여기에 Lua 로직을 더해 요청 헤더를 보고 분기하거나, 간단한 인증/검증을 하거나, 캐시 키를 세밀하게 만들거나, 응답을 일부 가공하는 식의 처리를 넣을 수 있습니다.

마이그레이션 구조에서 OpenResty는 입구 계층입니다. 어떤 URL은 기존 WAS로 보내고, 어떤 URL은 새 Nuxt/Nitro 서버로 보낼 수 있습니다. 예를 들어 `/legacy/**`는 WAS로 보내고, `/products/**`는 Nuxt/Nitro로 보내는 식으로 점진 전환을 할 수 있습니다.

다만 OpenResty가 모든 업무 로직을 가져가면 구조가 흐려집니다. 주문 생성, 결제 승인, 회원 권한 판단처럼 핵심 도메인 규칙은 WAS에 남기는 편이 안전합니다. OpenResty는 앞단에서 빠르게 판단할 수 있는 라우팅, 캐시, 리다이렉트, 간단한 헤더 처리 정도에 집중하는 것이 좋습니다.

## 그래서 뭐가 좋은데?

OpenResty가 있으면 브라우저 요청의 입구를 한 곳에서 통제할 수 있습니다.

- 기존 WAS와 새 Nuxt/Nitro를 URL 단위로 나눠 보낼 수 있습니다.
- 정적 파일이나 공개 캐시 응답은 뒤쪽 서버까지 가지 않고 빠르게 줄 수 있습니다.
- 오래된 URL을 새 URL로 redirect할 수 있습니다.
- 요청 헤더, 쿠키, 경로를 보고 간단한 분기 처리를 할 수 있습니다.
- Nuxt/Nitro나 WAS 앞에서 공통 timeout, cache, proxy 정책을 둘 수 있습니다.

하지만 OpenResty는 업무 서버가 아닙니다. 앞단에서 너무 많은 도메인 판단을 넣으면 어디서 문제가 생겼는지 추적하기 어려워집니다. 입구에서 할 일과 WAS가 할 일을 구분하는 것이 중요합니다.
